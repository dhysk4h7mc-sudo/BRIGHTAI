## PHASE 0 — إصلاحات حرجة (تُنفّذ أولاً)

### P0-1 — إصلاح طبقة البيانات الحية `[CR-001]`

```plaintext
الهدف: إزالة حالة "Production API · Degraded" و"Unknown DB" وملء الـ skeletons الفارغة على كل صفحات Kernel.
نفّذ:
1. تتبّع مصدر الـ health badge في غرفة تشغيل Kernel وحدّد من أين يقرأ حالة الـ API/DB.
2. أصلح نقطة الاتصال أو وفّر fallback بمصدر بيانات حقيقي (لا بيانات وهمية ثابتة).
3. استبدل كل skeleton دائم بحالة بيانات فعلية، أو empty state واضح إن لم توجد بيانات بعد.
معيار القبول: لا تظهر "Degraded" ولا "Unknown DB"؛ كل لوحة تعرض بيانات حقيقية أو empty state مقصود.
```

### P0-2 — إزالة توست "offline" الدائم `[CR-002]`

```plaintext
الهدف: إيقاف ظهور توست "offline" الدائم الذي يحجب جزءاً من الواجهة على كل صفحات Kernel.
نفّذ:
1. حدّد منطق كشف الاتصال (online/offline detection) المسؤول عن التوست.
2. اجعل التوست يظهر فقط عند انقطاع فعلي مؤكّد، ويختفي تلقائياً عند العودة.
3. تأكد أنه لا يحجب أي عنصر تفاعلي (z-index/position) وأنه قابل للإغلاق.
معيار القبول: التوست لا يظهر في الحالة الطبيعية، ولا يحجب أي زر أو محتوى.
```

## PHASE 1 — INDEX EVERYTHING (الفهرسة)

### P1-1 — تدقيق فهرسة شامل `[القاعدة #1]`

```plaintext
افحص كل صفحات الموقع (~129) وتأكد أن كل صفحة ذات قيمة عامة بها <meta name="robots" content="index, follow">.
استثنِ فقط: components/ وfont-demo (عروض داخلية). أنشئ جدولاً بكل صفحة noindex وسبب بقائها.
معيار القبول: 0 صفحة منتج/محتوى عليها noindex.
```

### P1-2 — تمييز meta وkeywords لكل صفحة Kernel `[HI-003]`

```plaintext
لكل صفحة من صفحات Kernel الـ11 اكتب <title> و<meta description> فريدة تعكس وظيفة الصفحة وكلمتها المفتاحية،
وأزل تكرار keywords الموحّد. تجنّب التشابه الذي يسبب cannibalization.
معيار القبول: لا توجد صفحتان بنفس الـ title أو الـ description.
```

### P1-3 — إصلاح H1 في `/kernel/`و`/kernel/stats/``[HI-002]`

```plaintext
استبدل H1 الضعيف بـ H1 واحد واضح غني بالكلمة المفتاحية ومكتوب باللهجة السعودية المهنية.
مثال للوحة: "غرفة تشغيل الذكاء الاصطناعي — راقب كل شي من مكان واحد".
معيار القبول: H1 واحد فقط لكل صفحة، يحوي الكلمة المفتاحية الأساسية.
```

### P1-4 — إضافة WebApplication/SoftwareApplication Schema `[ME-001]`

```plaintext
أضف JSON-LD من نوع SoftwareApplication/WebApplication على صفحات Kernel وصفحة المنتج،
مع applicationCategory وoperatingSystem وoffers ووصف عربي. حافظ على Schema الحالي.
معيار القبول: يمر الفحص في Rich Results Test بلا أخطاء.
```

### P1-5 — sitemap محدّث + ربط في robots.txt

```plaintext
ولّد sitemap.xml يشمل كل الصفحات المفهرسة مع lastmod، واربطه في robots.txt.
معيار القبول: sitemap صالح ويشمل كل صفحات Kernel الـ11 والصفحات التسويقية.
```

## PHASE 2 — اللهجة السعودية `[HI-001]`

### P2-1 — إعادة كتابة 11 Hero لصفحات Kernel

```plaintext
أعد كتابة قسم Hero (H1 + جملة الوصف + CTA) لكل صفحة من الـ11 باللهجة السعودية المهنية (مثل أسلوب الـ homepage: "الزبدة"، "وش تقدر تسوي").
حافظ على الرصانة المؤسسية ولا تبالغ بالعامية. اربط كل Hero بقيمة الصفحة.
معيار القبول: 11 Hero مميزة باللهجة + CTA واضح لكل وحدة.
```

### P2-2 — توحيد نبرة CTAs عبر الموقع

```plaintext
وحّد صياغة أزرار الإجراء باللهجة السعودية (مثل: "جرّبه الحين"، "اطلب عرض"، "شوف كيف يشتغل")
عبر Kernel والموقع التسويقي.
معيار القبول: لا CTA بصياغة فصحى جافة متبقية في الأسطح الرئيسية.
```
